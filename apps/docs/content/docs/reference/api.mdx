This is a task-oriented reference for the public package exports. Generic types
retain additional schema, selection, grouping, and context constraints; a method
name in this table does not mean every argument is valid for every object.

## Construction and compilation

| API | Purpose |
| --- | --- |
| `new Kysoql<DB>(config?)` | Main entry point; inherits `QueryCreator<DB>`. |
| `new QueryCreator<DB>(config?)` | Same query-creation contract. |
| `QueryCreatorConfig.executor?` | Optional `QueryExecutor` for API execution. |
| `QueryCreatorConfig.queryCompiler?` | Optional `QueryCompiler`; defaults to `DefaultQueryCompiler`. |
| `selectFrom(object)` | Starts an unselected root builder for a schema object. |
| `compile()` | Returns `CompiledQuery<O>` with `soql` and `query`. |
| `toOperationNode()` | Returns the current operation tree without executing. |

A `QueryCompiler` instance can also be passed directly to the constructor for
compile-only compatibility. Prefer the config object when combining an executor
and compiler. `CompiledQuery` has a type-only output carrier; it does not contain
an SQL-style parameter array or a runtime row validator.

## Root record query

| Method | Behaviour / guide |
| --- | --- |
| `select(fieldOrFields)` | Add direct or parent-path selections. [Selecting](/docs/guides/selecting). |
| `select(callback)` | Add supported aliased SELECT functions, or enter count/aggregate mode from an unselected builder. |
| `selectFields(selector)` | `standard`, `custom`, or `all`; requires a complete field schema and is subject to bounds and overlap checks. |
| `selectSubquery(relationship, callback)` | Add a generated child relationship. [Relationships](/docs/guides/relationships). |
| `selectTypeOf(relationship, callback)` | Add polymorphic `when`/`else` selections. [Polymorphism](/docs/guides/polymorphism). |
| `where(field, operator, value)` | Append a typed predicate with AND. |
| `where(callback)` | Append grouped or function predicates. [Filtering](/docs/guides/filtering). |
| `orderBy(fieldOrCallback, direction?, nulls?)` | Append sortable-field or distance ordering. |
| `limit(n)`, `offset(n)` | Replace pagination clauses. [Pagination](/docs/guides/ordering-and-pagination). |
| `groupBy(fieldOrFieldsOrCallback)` | Enter ordinary grouped mode only before ordinary selections. |
| `$call(callback)`, `$if(condition, callback)` | Compose while retaining specialised types. [Composition](/docs/guides/composition). |
| `clearSelect()`, `clearWhere()`, `clearOrderBy()`, `clearLimit()`, `clearOffset()` | Reset the named clause immutably. |
| `execute()`, `executeAll()` | Execute ordinary/QueryAll mode with a configured executor. |
| `apex()`, `dynamicApex()` | Switch to a compile-only specialised builder. |

## Aggregate query

Enter using aliased aggregate `select` on an unselected root, or ordinary
`groupBy` on an unselected root. See [aggregates](/docs/guides/aggregates).

| Method | Behaviour |
| --- | --- |
| `select(callback)` | Add aliased aggregate, grouped-date, or grouping selections as applicable. |
| `groupBy(fieldOrFieldsOrCallback)` | Accumulate ordinary grouping fields/expressions. |
| `groupByRollup(fields)`, `groupByCube(fields)` | Accumulate advanced grouping, at most three fields. |
| `select(fieldOrFields)` | Select fields already in the grouping set. |
| `having(field, operator, value)` / `having(callback)` | Filter groups using permitted grouped/aggregate expressions. |
| `orderBy(fieldOrCallback, direction?, nulls?)` | Order grouped fields or supported unaliased functions. |
| `limit(n)`, `offset(n)` | Grouped pagination; unavailable as valid ungrouped pagination. |
| `clearGroupBy()` | Remove grouping only when no dependent state remains. |
| `clearSelect()`, `clearWhere()`, `clearOrderBy()`, `clearLimit()`, `clearOffset()` | Clear applicable clauses. |
| `$call`, `$if`, `compile`, `toOperationNode`, `execute`, `executeAll`, `apex`, `dynamicApex` | Preserve the aggregate mode/output contracts. |

## Scalar count query

`select(({ fn }) => fn.count())` returns `CountQueryBuilder<DB, TB>`.
It exposes `where`, `limit`, `clearWhere`, `clearLimit`, `$call`, `$if`,
`compile`, `toOperationNode`, `execute`, `executeAll`, `apex`, and `dynamicApex`,
plus eligible root-specific clauses below. It has no `select`, `orderBy`,
`offset`, `groupBy`, or `having`. Execution returns `number`.

## Root-specific Salesforce clauses

Normal record, aggregate, and count builders model these methods with
object/capability-specific constraints:

| Method | Constraint / guide |
| --- | --- |
| `usingScope(scope)` | Generated scope union. [Scopes](/docs/advanced/scopes-and-visibility). |
| `forView()`, `forReference()` | Generated MRU capability; modes replace one another. |
| `withRecordVisibilityContext(options)` | Non-empty supported options; conflicts with another filtering WITH. |
| `withDataCategory(group, selector, categories)` | Generated categories; at most three different groups. [Knowledge](/docs/advanced/knowledge-and-feeds). |
| `updateTracking()`, `updateViewstat()` | Knowledge article objects only; modes accumulate. |
| `withUserId(userId)` | `UserProfileFeed` only. |
| `setOptions(options)` | DLO record/aggregate/count, simple DMO record queries. [Data 360](/docs/advanced/data-360). |

There is no general `with(...)` raw-clause method. Configure these on the normal
builder before entering Apex where appropriate; the Apex interface does not
re-expose the same root methods.

## Child and semi-join builders

`RelationshipSubqueryBuilder` provides ordinary `select`, supported function
`select`, `selectFields`, `selectSubquery`, `where`, `orderBy`, `limit`, their
applicable clearing helpers, `$call`, `$if`, `toOperationNode`, and the explicit
`pilot.offset`/`pilot.clearOffset` namespace. Apex-created child builders enable
supported WHERE binds. There is no root `compile`/`execute`, general `offset`,
aggregate/HAVING, `TYPEOF`, semi-join, or root Salesforce clause surface.

`SemiJoinQueryCreator.selectFrom` returns an inner builder whose one `select`
chooses a compatible ID/reference field. It supports `where`, `clearWhere`,
`$call`, and `$if`. The selected builder cannot add another selected field.
There is no ordering, pagination, nested semi-join, or independent execution.

`TypeOfBuilder.when(object, fields)` adds a typed branch;
`else(fields)` completes a supported fallback. See
[polymorphism](/docs/guides/polymorphism) for restrictions and returned unions.

## Apex builders

All Apex variants expose `compile`, `toOperationNode`, `where`, `limit`,
`clearWhere`, `clearLimit`, `$call`, `$if`, `allRows`, `withUserMode`, and
`withSystemMode`. They never expose `execute`/`executeAll`.

| Builder | Additional surface |
| --- | --- |
| `ApexSelectQueryBuilder` | `forUpdate`, `selectSubquery`, `offset`, `clearOffset`, `clearOrderBy`. |
| `ApexAggregateSelectQueryBuilder` | `offset`, `clearOffset`, `clearOrderBy`, guarded `clearGroupBy`. |
| `ApexCountQueryBuilder` | No offset, locking, sorting, or further selection. |
| Dynamic variants | Bound `setOptions(apexBind<ApexDatabaseQueryOptions>(...))`; unavailable in static context. |

Complete ordinary selections, sorting, grouping, and HAVING before the context
switch. See [Apex](/docs/apex/overview) and [bindings](/docs/apex/bindings).

## Expression helpers

There is no standalone global `fn` export. It is supplied by the appropriate
selection/filter/grouping callback, with a surface suited to that context.

| Family | Helpers |
| --- | --- |
| Aggregate | `count`, `countDistinct`, `sum`, `avg`, `min`, `max`. |
| Date | `calendarMonth`, `calendarQuarter`, `calendarYear`, `dayInMonth`, `dayInWeek`, `dayInYear`, `fiscalMonth`, `fiscalQuarter`, `fiscalYear`, `hourInDay`, `weekInMonth`, `weekInYear`, `dayOnly`, `convertTimezone`. |
| Display | `toLabel`, `convertCurrency`, `format`. |
| Geolocation | `geolocation`, `distance`. |
| Advanced grouping | `grouping`, for accumulated rollup/cube fields. |
| Boolean filter composition | Callable `eb`, plus `eb.and`, `eb.or`, `eb.not`. |
| Experimental | `eb.beta.formula`, WHERE only. |

Only selected row-producing expressions use `.as(alias)`; ordering and HAVING
callbacks use unaliased expressions. Read the corresponding guides for inputs,
result nullability, context, and grouping-identity requirements.

## Top-level value helpers

`soqlDate`, `soqlDateTime`, `soqlTime`, `soqlRelativeDate`, and `soqlCurrency`
construct [validated literals](/docs/guides/literals).
`apexBind`, `apexAdd`, `apexSubstring`, and `apexQueryField` construct
[Apex expression nodes](/docs/apex/bindings).

## Integration and extension exports

### Native REST

| Export or method | Contract |
| --- | --- |
| `createRestClient(options)` | Shared native GET transport with authentication, version, deadline, and URL controls. |
| `createRestExecutor(clientOrOptions, pagination?)` | A `RestExecutor` implementing all four core execution capabilities. |
| `executeQuery(query, options?)` / `executeAllQuery(query, options?)` | Collect root rows from ordinary Query / QueryAll. |
| `executeCountQuery(query, options?)` / `executeAllCountQuery(query, options?)` | Return bare `COUNT()` numbers in the selected mode. |
| `queryPages(query, options?)` | Async iterator of root `RestQueryPage<O>` envelopes. |
| `iterateQuery(query, options?)` | Async iterator of root records. |
| `queryMore<Row>(locator, options?)` | One explicit root/child continuation page. |
| `authenticateClientCredentials(options)` | One native client-credentials token exchange. |
| `refreshAccessToken(options)` | One native refresh-token exchange. |
| `DEFAULT_API_VERSION` | Pinned string `"65.0"`; not automatic version negotiation. |

`@kysoql/rest` exports the corresponding `RestClient`, `RestClientOptions`,
`RestExecutor`, `RestPaginationOptions`, `RestQueryPage`, `RestQueryOptions`,
`RestGetOptions`, `RestRequestOptions`, `HttpOptions`, `AccessTokenProvider`,
`ClientCredentialsOptions`, `RefreshTokenOptions`, and `SalesforceOAuthSession`
types. Errors are `SalesforceRestError` (plus `SalesforceRestErrorDetail`),
`SalesforceResponseError`, `SalesforceQueryLimitError`, and `SalesforceOAuthError`.

Request options accept `signal` and `timeoutMs`; query iteration additionally
accepts `queryAll`. Pagination options accept `batchSize`, `maxPages`, and
`maxRecords`. See [execution](/docs/guides/execution) and
[authentication](/docs/guides/authentication) for defaults and boundaries.

### Optional adapters and codegen

`@kysoql/jsforce` exports `createJsforceExecutor` and the public interfaces
`JsforceConnection`, `JsforceExecutor`, `JsforceQueryResult`, and
`JsforceCountQueryResult`.

`@kysoql/codegen` exports `createRestDescribeClient`, `generateSchema`, `loadSchema`, `renderSchema`,
`GenerateSchemaOptions` (including optional `fields`), `SalesforceDescribeClient`, and normalized Describe
interfaces. See [schema generation](/docs/getting-started/schema-generation).

Core exports [schema helpers](/docs/reference/schema-types), builder/expression
types, `CompiledQuery`, `QueryCompiler`, `QueryCompileContext`, and
`QueryExecutor`. It also exposes operation-node **types** for inspection and
integration; those type exports are not a supported collection of runtime
node-factory imports. Prefer the builder to hand-authoring ASTs or depending on
private `#/...` package paths.

## Codegen configuration

`@kysoql/codegen` exports `defineConfig`, `KysoqlConfig`, `ObjectFieldFilter`,
and `ObjectFieldFilters` for
[`kysoql.config.ts`](/docs/getting-started/configuration). They configure the CLI's
API version, object list, per-object field rules, output file, and schema interface name. They are separate from
`QueryCreatorConfig`, which configures runtime query construction and execution.

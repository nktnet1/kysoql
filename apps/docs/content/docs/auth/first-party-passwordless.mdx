title: "First-party passwordless login"
description: "Use Salesforce OAuth 2.0 for First-Party Applications passwordless email or SMS OTP login."

---

The first-party passwordless flow sends an OTP to the user's verified email
address or phone number, then resumes the authorization challenge with the OTP to
obtain an authorization code.

Salesforce reference: [Headless Passwordless Login for Private Clients](https://help.salesforce.com/s/articleView?id=remoteaccess_auth_challenge_passwordless_login.htm&language=en_US&type=5).

## Initialize passwordless login

```ts
import { requestFirstPartyAuthorizationChallenge } from "@kysoql/auth";

export function beginPasswordless(
  username: string,
  clientAssertion: string,
  codeChallenge: string,
) {
  return requestFirstPartyAuthorizationChallenge({
    siteUrl: "https://customers.example.my.site.com/customers",
    parameters: {
      username,
      login_type: "email",
      client_assertion: clientAssertion,
      client_id: "external-client-app-id",
      code_challenge: codeChallenge,
      scope: "api refresh_token",
    },
  });
}
```

A successful initialization is still a challenge response: Salesforce returns an
`auth_session` and a login state indicating that the OTP was sent.

## Submit the OTP

```ts
import { requestFirstPartyAuthorizationChallenge } from "@kysoql/auth";

export function submitPasswordlessOtp(authSession: string, otp: string) {
  return requestFirstPartyAuthorizationChallenge({
    siteUrl: "https://customers.example.my.site.com/customers",
    parameters: {
      auth_session: authSession,
      login_otp: otp,
    },
  });
}
```

When Salesforce returns `kind: "authorized"`, exchange the authorization code
through [`exchangeAuthorizationCode()`](/docs/auth/web-server-pkce) using the
matching PKCE verifier.

For identifier-based discovery instead of a Salesforce username, follow
Salesforce's `login_hint`/`customdata` requirements for this flow.

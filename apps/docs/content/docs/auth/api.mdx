Flow-specific usage is documented in [authentication flows](/docs/auth/flows).
For application code, prefer the `SalesforceAuth` class; the standalone helpers
remain exported for lower-level composition and backwards compatibility.

## SalesforceAuth

Create one client with the Salesforce login, My Domain, or Experience Cloud site
URL plus the OAuth client ID:

```ts
import { SalesforceAuth } from "@kysoql/auth";

const auth = new SalesforceAuth({
  loginUrl: "https://login.salesforce.com",
  clientId: "external-client-app-id",
});
```

The constructor also accepts the shared request options `fetch`, `signal`, and
`timeoutMs`. Per-operation request options override those defaults.

| Method | Purpose |
| --- | --- |
| `jwtBearer(options)` | Create and exchange an RS256 JWT bearer assertion in one call. |
| `clientCredentials(options)` | Perform a client-credentials token exchange. |
| `authorizationUrl(options)` | Build a web-server authorization-code URL, including PKCE parameters. |
| `exchangeAuthorizationCode(options)` | Exchange a standard authorization code. |
| `refreshToken(options)` | Refresh a standard OAuth session and persist rotation when configured. |
| `createClientAssertion(options)` | Create a short-lived `private_key_jwt` client assertion. |
| `samlBearer(options)` | Exchange an OAuth SAML bearer assertion. |
| `samlAssertion(options)` | Exchange Salesforce's SAML API assertion. |
| `tokenExchange(options)` | Exchange a supported subject token. |
| `requestDeviceAuthorization(options)` | Start device authorization. |
| `pollDeviceAuthorization(options)` | Perform one device-token poll. |
| `exchangeHybridAuthorizationCode(options)` | Exchange a hybrid web-server authorization code. |
| `refreshHybridToken(options)` | Refresh a hybrid application session. |
| `generatePkcePair()` | Generate an RFC 7636 verifier and S256 challenge. |
| `codeCredentialsAuthorization(options)` | Build an Experience Cloud Code and Credentials request. |
| `guestAuthorization(options)` | Build the Experience Cloud guest authorization request. |
| `firstPartyAuthorizationChallenge(options)` | Call the first-party `authorization_challenge` endpoint. |
| `storedRefreshToken(options)` | Create a refresh-token-backed session manager bound to this client. |

All token exchanges return `SalesforceOAuthSession`, whose REST-relevant fields
are `accessToken`, `instanceUrl`, and optional `refreshToken`. `scope`, `idToken`,
and `issuedAt` are retained when Salesforce returns them.

## Lower-level OAuth functions

The functional API exposes the same primitives with all configuration passed to
each call:

| Export | Purpose |
| --- | --- |
| `createAuthorizationUrl(options)` | Build a web-server authorization-code URL. |
| `exchangeAuthorizationCode(options)` | Exchange an authorization code for a Salesforce bearer session. |
| `refreshAccessToken(options)` | Exchange a refresh token and persist rotation when a store is supplied. |
| `authenticateClientCredentials(options)` | Perform a client-credentials token exchange against a My Domain. |
| `authenticateJwtBearer(options)` | Exchange an already-signed JWT bearer assertion. |
| `authenticateSamlBearer(options)` | Exchange an OAuth SAML bearer assertion. |
| `authenticateSamlAssertion(options)` | Use Salesforce's SAML assertion API flow. |
| `exchangeToken(options)` | Run OAuth 2.0 token exchange with a supported subject-token type. |
| `requestDeviceAuthorization(options)` | Start device authorization and return the user/device codes. |
| `pollDeviceAuthorization(options)` | Perform one device token poll. |
| `exchangeHybridAuthorizationCode(options)` | Exchange a hybrid web-server authorization code. |
| `refreshHybridAccessToken(options)` | Refresh a hybrid application session. |

`AuthorizationCodeOptions.authRequestType` and `uvidHint` carry the token-endpoint
headers required by headless guest code exchanges. `loginUrl` accepts a Salesforce
OAuth base URL, including an Experience Cloud site path when the flow is hosted
there.

`SalesforceOAuthError` represents an OAuth HTTP failure and exposes `status` plus
an optional OAuth `code`. `SalesforceOAuthResponseError` represents a malformed
successful response.

## PKCE and JWT primitives

| Export | Purpose |
| --- | --- |
| `generatePkcePair()` | Generate an RFC 7636 verifier and S256 challenge. |
| `createPkceChallenge(verifier)` | Derive an S256 challenge from an existing verifier. |
| `createJwtBearerAssertion(options)` | Create and RS256-sign a Salesforce JWT bearer assertion with Web Crypto. |
| `createOAuthClientAssertion(options)` | Create an RS256 `private_key_jwt` client assertion for a Salesforce token endpoint. |

Both assertion helpers accept `PrivateKeyInput`: an RS256 `CryptoKey`, a raw PEM
string, a PEM file path, or a file URL. Raw PEM string values are trimmed before
parsing. Relative file paths resolve from `process.cwd()`; use a file URL when the
key should resolve relative to a module. Pass a `CryptoKey` when a key manager or
custom runtime already owns key loading.

## Headless identity primitives

| Export | Purpose |
| --- | --- |
| `createCodeCredentialsAuthorizationRequest(options)` | Build an Experience Cloud named-user Code and Credentials POST request. |
| `createHeadlessGuestAuthorizationRequest(options)` | Build the guest Code and Credentials authorization request with Salesforce UVID/JWT prefix handling. |
| `requestFirstPartyAuthorizationChallenge(options)` | Call the OAuth 2.0 first-party authorization-challenge endpoint. |

`CodeCredentialsAuthorizationOptions` is a discriminated union for named-user
credentials and headless user discovery. Named-user requests can use HTTP Basic
or POST-body credentials; user-discovery requests use `loginHint` plus POST-body
credentials. `uvidHint` sends the plain UVID body field and `uvidHintToken` sends
the JWT-based token in `Uvid-Hint`.

The first-party helper returns a discriminated `FirstPartyAuthorizationChallenge`
result so resumable `auth_session` responses are not confused with terminal OAuth
failures. Form bodies are the default; `bodyFormat: "json"` supports structured
first-party registration payloads. `accessToken` adds an `Authorization: Bearer`
header for registration policies that require an authenticated integration user.

## Refresh-token stores

| Export | Purpose |
| --- | --- |
| `RefreshTokenStore` | Three-method persistence contract. |
| `createMemoryRefreshTokenStore(initial?)` | Process-local token storage. |
| `createLocalStorageRefreshTokenStore(options)` | Browser/Web Storage-compatible persistence. |
| `createRedisRefreshTokenStore(options)` | Redis-compatible `get`/`set`/`del` persistence without a Redis dependency. |
| `StorageLike` | Minimal Web Storage-compatible interface. |
| `RedisLike` | Minimal Redis client interface consumed by the adapter. |

## Managed refresh

`auth.storedRefreshToken(options)` and the lower-level
`createStoredRefreshTokenAuth(options)` both return:

| Member | Purpose |
| --- | --- |
| `getSession()` | Return the current session, performing the first refresh when necessary. |
| `refresh()` | Single-flight a refresh-token exchange. |
| `accessTokenProvider` | Provider compatible with the `@kysoql/rest` client/executor. |
| `clear()` | Drop the in-memory session and delete the stored refresh token. |

`clientAssertion` is a callback, not a static token, so short-lived JWT client
assertions can be regenerated for every refresh. `clientSecretTransport` selects
POST-body or HTTP Basic client-secret transport, and `refreshMode: "hybrid"`
switches the manager to Salesforce's hybrid refresh grant.

JWT bearer is the default Kysoql recommendation for a server-to-server
integration that can protect a private key. Salesforce validates an RS256-signed
JWT against the certificate registered for the external client app and returns an
access token for the pre-authorized user.

Salesforce reference: [OAuth 2.0 JWT Bearer Flow for Server-to-Server Integration](https://help.salesforce.com/s/articleView?id=xcloud.remoteaccess_oauth_jwt_flow_ca.htm&language=en_US&type=5).

## Authenticate

```ts
import {
  authenticateJwtBearer,
  createJwtBearerAssertion,
} from "@kysoql/auth";

export async function authenticateSalesforce(privateKey: CryptoKey) {
  const loginUrl = "https://login.salesforce.com";
  const assertion = await createJwtBearerAssertion({
    clientId: "external-client-app-id",
    username: "integration@example.com",
    loginUrl,
    privateKey,
  });

  return authenticateJwtBearer({
    loginUrl,
    assertion,
  });
}
```

`createJwtBearerAssertion()` creates the Salesforce JWT claims and signs them with
Web Crypto. The private key must be an RSASSA-PKCS1-v1_5 `CryptoKey`, which maps
to RS256 in the JWT header.

The helper defaults the assertion lifetime to 180 seconds and rejects lifetimes
above 300 seconds. The application is responsible for importing or obtaining the
private key from its file system, secret manager, KMS, HSM, or equivalent key
provider.

## Salesforce setup

Configure the external client app for JWT bearer, register the matching X.509
certificate, and authorize the integration user according to Salesforce policy.
Salesforce does not issue a refresh token for this flow.

Salesforce setup reference: [Configure a JWT Bearer Flow](https://help.salesforce.com/s/articleView?id=configure_oauth_jwt_flow_external_client_apps.htm&language=en_US&type=5).

## Renew an expired session

Generate a new short-lived assertion and call `authenticateJwtBearer()` again.
Because no refresh token is involved, there is nothing to persist in
[refresh-token storage](/docs/auth/storage).

For `private_key_jwt` client authentication used inside another OAuth flow, see
[private-key client authentication](/docs/auth/private-key-jwt). It is distinct
from the JWT bearer grant documented on this page.

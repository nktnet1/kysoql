## Generated capabilities

This generator identifies Data Lake Objects from the `__dll` suffix and Data
Model Objects from `__dlm`, then emits `setOptionsCapability`. It does not discover
arbitrary Data 360 SQL capabilities or grant access to a dataspace.

Use the actual generated object and field names for your org. The names in the
following examples are illustrative, not additional packages or built-in objects.

## Data Lake Object options

```ts
import { db } from "./db";

const lakeRows = db
  .selectFrom("ContactPoint__dll")
  .select(["Id", "EmailOptIn__c"])
  .where("EmailOptIn__c", "=", "")
  .setOptions({ dataspace: "default", honorEmptyStrings: true });
```

For DLOs, `setOptions` requires a non-empty `dataspace` and optionally accepts
`honorEmptyStrings`. DLO record, aggregate-result, and bare-count builders support
this shape. The compiler emits `SET OPTIONS` at the end of the query.

The requirement is enforced when `setOptions` is used; the builder does not
silently add a dataspace to every DLO query. Choose the appropriate dataspace
explicitly rather than assuming the org's configuration.

## Data Model Object options

```ts
import { db } from "./db";

const modelRows = db
  .selectFrom("UnifiedIndividual__dlm")
  .select("Id")
  .setOptions({ honorEmptyStrings: true });
```

The simple DMO record-query surface accepts `honorEmptyStrings` only. DMO
aggregate/count option support is not exposed. Ordinary CRM objects have no
Data 360 `setOptions` capability.

`honorEmptyStrings: true` distinguishes empty strings from null in the supported
Data 360 contexts. Do not assume ordinary Salesforce CRM string-filter behaviour
is identical. See Salesforce's [SET OPTIONS reference](https://developer.salesforce.com/docs/platform/salesforce-soql-sosl/guide/sforce-api-calls-soql-select-set-options.html)
for server-side behaviour and context restrictions.

## Managed dynamic Apex options

Bound `Database.QueryOptions` is a separate feature, not the object-shaped Data
360 overload:

```ts
import { apexBind, type ApexDatabaseQueryOptions } from "@kysoql/core";
import { db } from "./db";

const compiled = db
  .selectFrom("Account")
  .select(["Id", "Name"])
  .dynamicApex()
  .setOptions(apexBind<ApexDatabaseQueryOptions>("queryOptions"))
  .compile();
// SELECT Id, Name FROM Account SET OPTIONS :queryOptions
```

`ApexDatabaseQueryOptions` is a type-only marker. Kysoql does not instantiate
that Apex object, set `explicitNamespace` on your behalf, or execute the query.
The managed Apex caller must supply the options instance and use the supported
dynamic-query API. Static `.apex()` does not enable this overload.

The dynamic overload is available on record, aggregate, and count Apex builders.
It does not turn `setOptions({ explicitNamespace: true })` into a supported
TypeScript API, nor make it valid in an ordinary Salesforce REST or JSforce request.

This is a task-oriented reference for the public package exports. Generic types
retain additional schema, selection, grouping, and context constraints; a method
name in this table does not mean every argument is valid for every object.

## Construction and compilation

| API | Purpose |
| --- | --- |
| `new Kysoql<DB>(config?)` | Main entry point; inherits `QueryCreator<DB>`. |
| `new QueryCreator<DB>(config?)` | Same query-creation contract. |
| `QueryCreatorConfig.executor?` | Optional `QueryExecutor` for API execution. |
| `QueryCreatorConfig.queryCompiler?` | Optional `QueryCompiler`; defaults to `DefaultQueryCompiler`. |
| `QueryCreatorConfig.plugins?` | Optional ordered `KysoqlPlugin` list. |
| `withPlugin(plugin)` | Returns a new creator with the plugin appended; the original creator is unchanged. |
| `withoutPlugins()` | Returns an equivalent creator with the plugin pipeline removed. |
| `selectFrom(object)` | Starts an unselected root builder for a schema object. |
| `compile()` | Returns `CompiledQuery<O>` with `soql` and `query`. |
| `executeQuery(compiledQuery, options?)` | Executes a previously compiled query with the configured executor; preserves result aliases and accepts `{ signal }`. Bare `COUNT()` queries return `number`. |
| `toOperationNode()` | Returns the current plugin-transformed operation tree without executing. |

A `QueryCompiler` instance can also be passed directly to the constructor for
compile-only compatibility. Prefer the config object when combining an executor
and compiler. `CompiledQuery` has a type-only output carrier; it does not contain
an SQL-style parameter array or a runtime row validator. Use `executeQuery` when
building, compiling, and executing need to happen in separate layers:

```ts
import { db } from "./db";

const compiled = db.selectFrom("Account").select(["Id", "Name"]).compile();
const rows = await db.executeQuery(compiled);
```

Plugins can transform the immutable query tree before compilation and when
`toOperationNode()` exposes it, and can optionally transform executor results. This
API is Kysely-inspired, but `KysoqlPlugin` is a Kysoql-specific contract rather than
a drop-in `KyselyPlugin`. Hooks run in registration order. `transformQuery` must
return a `SelectQueryNode`; Kysoql rejects a plugin that replaces the root with
another node kind. A plugin attached
with `withPlugin()` also applies to builders created from the returned instance;
`withoutPlugins()` removes the pipeline without mutating the original instance.
Result hooks receive transport results before Kysoql applies field-alias projection.
Each compile/execution lifecycle also receives a stable `queryId`, allowing plugins
to correlate query and result hooks even when multiple queries execute concurrently.

```ts
import type { KysoqlPlugin } from "@kysoql/core";
import { db } from "./db";

const tracePlugin: KysoqlPlugin = {
  transformQuery({ queryId, query }) {
    console.debug(queryId.queryId, "Compiling", query.from.name);
    return query;
  },
  transformResult({ queryId, result }) {
    console.debug(queryId.queryId, "Executed query");
    return result;
  },
};

const tracedDb = db.withPlugin(tracePlugin);
const accounts = await tracedDb.selectFrom("Account").select("Id").execute();
```

## Root record query

| Method | Behaviour / guide |
| --- | --- |
| `select(fieldOrFields)` | Add direct or parent-path selections. [Selecting](/docs/framework/guides/selecting). |
| `select(callback)` | Add supported aliased SELECT functions, or enter count/aggregate mode from an unselected builder. |
| `selectFields(selector)` | `standard`, `custom`, or `all`; requires a complete field schema and is subject to bounds and overlap checks. |
| `selectSubquery(relationship, callback)` | Add a generated child relationship. [Relationships](/docs/framework/guides/relationships). |
| `selectTypeOf(relationship, callback)` | Add polymorphic `when`/`else` selections. [Polymorphism](/docs/framework/guides/polymorphism). |
| `where(field, operator, value)` | Append a typed predicate with AND. |
| `where(callback)` | Append grouped or function predicates. [Filtering](/docs/framework/guides/filtering). |
| `orderBy(fieldOrCallback, direction?, nulls?)` | Append sortable-field or distance ordering. |
| `limit(n)`, `offset(n)` | Replace pagination clauses. [Pagination](/docs/framework/guides/ordering-and-pagination). |
| `groupBy(fieldOrFieldsOrCallback)` | Enter ordinary grouped mode only before ordinary selections. |
| `$call(callback)`, `$if(condition, callback)` | Compose while retaining specialised types. [Composition](/docs/framework/guides/composition). |
| `$castTo<T>()`, `$narrowType<T>()`, `$assertType<T>()` | Kysely-inspired, type-only result helpers; generated SOQL is unchanged. |
| `clearSelect()`, `clearWhere()`, `clearOrderBy()`, `clearLimit()`, `clearOffset()` | Reset the named clause immutably. |
| `execute()`, `executeAll()` | Execute ordinary/QueryAll mode with a configured executor; both accept `{ signal }`. |
| `executeTakeFirst()`, `executeTakeFirstOrThrow()` | Return the first row or throw `NoResultError`; both accept `{ signal }`, and the throwing form accepts a custom error constructor/factory. |
| `apex()`, `dynamicApex()` | Switch to a compile-only specialised builder. |

## Aggregate query

Enter using aliased aggregate `select` on an unselected root, or ordinary
`groupBy` on an unselected root. See [aggregates](/docs/framework/guides/aggregates).

| Method | Behaviour |
| --- | --- |
| `select(callback)` | Add aliased aggregate, grouped-date, or grouping selections as applicable. |
| `groupBy(fieldOrFieldsOrCallback)` | Accumulate ordinary grouping fields/expressions. |
| `groupByRollup(fields)`, `groupByCube(fields)` | Accumulate advanced grouping, at most three fields. |
| `select(fieldOrFields)` | Select fields already in the grouping set. |
| `having(field, operator, value)` / `having(callback)` | Filter groups using permitted grouped/aggregate expressions. |
| `orderBy(fieldOrCallback, direction?, nulls?)` | Order grouped fields or supported unaliased functions. |
| `limit(n)`, `offset(n)` | Grouped pagination; unavailable as valid ungrouped pagination. |
| `clearGroupBy()` | Remove grouping only when no dependent state remains. |
| `clearSelect()`, `clearWhere()`, `clearOrderBy()`, `clearLimit()`, `clearOffset()` | Clear applicable clauses. |
| `$call`, `$if`, `$castTo`, `$narrowType`, `$assertType`, `compile`, `toOperationNode`, `execute`, `executeTakeFirst`, `executeTakeFirstOrThrow`, `executeAll`, `apex`, `dynamicApex` | Preserve the aggregate mode/output contracts. |

## Scalar count query

`select(({ fn }) => fn.count())` returns `CountQueryBuilder<DB, TB>`.
It exposes `where`, `limit`, `clearWhere`, `clearLimit`, `$call`, `$if`,
`compile`, `toOperationNode`, `execute`, `executeAll`, `apex`, and `dynamicApex`,
plus eligible root-specific clauses below. It has no `select`, `orderBy`,
`offset`, `groupBy`, or `having`. Execution returns `number`.

## Root-specific Salesforce clauses

Normal record, aggregate, and count builders model these methods with
object/capability-specific constraints:

| Method | Constraint / guide |
| --- | --- |
| `usingScope(scope)` | Generated scope union. [Scopes](/docs/core/advanced/scopes-and-visibility). |
| `forView()`, `forReference()` | Generated MRU capability; modes replace one another. |
| `withRecordVisibilityContext(options)` | Non-empty supported options; conflicts with another filtering WITH. |
| `withDataCategory(group, selector, categories)` | Generated categories; at most three different groups. [Knowledge](/docs/core/advanced/knowledge-and-feeds). |
| `updateTracking()`, `updateViewstat()` | Knowledge article objects only; modes accumulate. |
| `withUserId(userId)` | `UserProfileFeed` only. |
| `setOptions(options)` | DLO record/aggregate/count, simple DMO record queries. [Data 360](/docs/core/advanced/data-360). |

There is no general `with(...)` raw-clause method. Configure these on the normal
builder before entering Apex where appropriate; the Apex interface does not
re-expose the same root methods.

## Child and semi-join builders

`RelationshipSubqueryBuilder` provides ordinary `select`, supported function
`select`, `selectFields`, `selectSubquery`, `where`, `orderBy`, `limit`, their
applicable clearing helpers, `$call`, `$if`, `$castTo`, `$narrowType`,
`$assertType`, `toOperationNode`, and the explicit
`pilot.offset`/`pilot.clearOffset` namespace. Apex-created child builders enable
supported WHERE binds. There is no root `compile`/`execute`, general `offset`,
aggregate/HAVING, `TYPEOF`, semi-join, or root Salesforce clause surface.

`SemiJoinQueryCreator.selectFrom` returns an inner builder whose one `select`
chooses a compatible ID/reference field. It supports `where`, `clearWhere`,
`$call`, and `$if`. The selected builder cannot add another selected field.
There is no ordering, pagination, nested semi-join, or independent execution.

`TypeOfBuilder.when(object, fields)` adds a typed branch;
`else(fields)` completes a supported fallback. See
[polymorphism](/docs/framework/guides/polymorphism) for restrictions and returned unions.

## Expression helpers

There is no standalone global `fn` export. It is supplied by the appropriate
selection/filter/grouping callback, with a surface suited to that context.

| Family | Helpers |
| --- | --- |
| Aggregate | `count`, `countDistinct`, `sum`, `avg`, `min`, `max`. |
| Date | `calendarMonth`, `calendarQuarter`, `calendarYear`, `dayInMonth`, `dayInWeek`, `dayInYear`, `fiscalMonth`, `fiscalQuarter`, `fiscalYear`, `hourInDay`, `weekInMonth`, `weekInYear`, `dayOnly`, `convertTimezone`. |
| Display | `toLabel`, `convertCurrency`, `format`. |
| Geolocation | `geolocation`, `distance`. |
| Advanced grouping | `grouping`, for accumulated rollup/cube fields. |
| Boolean filter composition | Callable `eb`, plus `eb.and`, `eb.or`, `eb.not`. |
| Experimental | `eb.beta.formula`, WHERE only. |

Selected functions and aggregates use `.as(alias)`. Plain selected fields use
Kysely-style `"Field as alias"` strings; ordering and HAVING callbacks still use
unaliased expressions. Read the corresponding guides for inputs, result
nullability, context, and grouping-identity requirements.

## Top-level value helpers

`soqlDate`, `soqlDateTime`, `soqlTime`, `soqlRelativeDate`, and `soqlCurrency`
construct [validated literals](/docs/framework/guides/literals).
`soqlMultiSelectAnd(...)` constructs Salesforce's semicolon-separated
multi-select-picklist AND operand while retaining generated picklist value types.
`soql.likeLiteral()` escapes `%` and `_` when a LIKE value should be literal rather
than a pattern.
`soql.raw()` is an explicit unsafe escape hatch for trusted SOQL syntax that the
builder does not model; it emits its fragment verbatim and must never contain
user-controlled input. `apexBind`, `apexAdd`, `apexSubstring`, and
`apexQueryField` construct [Apex expression nodes](/docs/core/apex/bindings).

## Integration contracts

Core exports [schema helpers](/docs/core/reference/schema-types), builder and
expression types, `CompiledQuery`, `QueryCompiler`, `QueryCompileContext`,
`QueryExecutor`, `KysoqlPlugin`, `QueryId`, `PluginTransformQueryArgs`,
`PluginTransformResultArgs`, `AbortableQueryOptions`, `QueryAbortSignal`,
`NoResultError`, and `NotNull`.
`applyQueryResultAliases(query, records)` is the low-level
result projection helper used by transport adapters for Kysely-style field
aliases; normal builder execution applies the same projection automatically. It
also exposes operation-node **types** for inspection and integration; those type
exports are not a supported collection of runtime node-factory imports. Prefer
the builder to hand-authoring ASTs or depending on private `#/...` package
paths.

Transport and schema-generation APIs are documented with their packages:

- [`@kysoql/rest` API](/docs/rest/api)
- [`@kysoql/codegen` API](/docs/codegen/api)
- [`@kysoql/jsforce` API](/docs/jsforce/api)

## Apex builders

All Apex variants expose `compile`, `toOperationNode`, `where`, `limit`,
`clearWhere`, `clearLimit`, `$call`, `$if`, `allRows`, `withUserMode`, and
`withSystemMode`. They never expose `execute`/`executeAll`.

| Builder | Additional surface |
| --- | --- |
| `ApexSelectQueryBuilder` | `forUpdate`, `selectSubquery`, `offset`, `clearOffset`, `clearOrderBy`. |
| `ApexAggregateSelectQueryBuilder` | `offset`, `clearOffset`, `clearOrderBy`, guarded `clearGroupBy`. |
| `ApexCountQueryBuilder` | No offset, locking, sorting, or further selection. |
| Dynamic variants | Bound `setOptions(apexBind<ApexDatabaseQueryOptions>(...))`; unavailable in static context. |

Complete ordinary selections, sorting, grouping, and HAVING before the context
switch. See [Apex](/docs/core/apex/overview) and [bindings](/docs/core/apex/bindings).

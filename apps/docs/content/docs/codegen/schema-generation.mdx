`@kysoql/codegen` turns Salesforce Describe metadata into a schema for
`Kysoql<YourSchema>`. Generate with an identity representative of your application,
and regenerate after changes to fields, relationships, picklists, or permissions.

For repeatable settings, create a
[`kysoql.config.ts`](/docs/codegen/configuration). The CLI automatically
loads it from the working directory. Explicit CLI flags override config values;
use `--no-config` with `--auth <module>` for a config-free settings run.

## CLI reference

```bash
pnpm exec kysoql generate --no-config \
  --auth config/salesforce.auth.ts \
  --object Account \
  --object Contact \
  --object Opportunity \
  --object User \
  --schema-name SalesforceSchema
```

| Option | Default | Behaviour |
| --- | --- | --- |
| `--api-version <version>` | Config or `65.0` | REST version without a `v` prefix; explicit flags take precedence. |
| `--auth <path>` | Config `auth` | Load a trusted module whose default export returns a Salesforce OAuth session. |
| `--config <path>` | Discover in the working directory | Select a JS/TS config explicitly; a missing file fails. |
| `--no-config` | `false` | Skip config discovery and evaluation; conflicts with `--config`. |
| `--object <api-name>` | Configured list or all queryable objects | Repeat once per object. Replaces, rather than appends to, the configured list. |
| `--output <path>` | Configured output, otherwise `src/kysoql/salesforce.generated.ts` when `./src` exists or `kysoql/salesforce.generated.ts` | Overrides the generated file. CLI paths use the working directory; parent directories are created. |
| `--schema-name <name>` | Configured name or `SalesforceSchema` | Name of the generated interface; must pass identifier validation. |
| `--help` | N/A | Displays generated oclif help. |

Authentication is explicit: define `auth` in config or pass `--auth <module>`. The provider should obtain a session with `@kysoql/auth` or another trusted mechanism. Codegen does not read `SF_ACCESS_TOKEN`, `SF_INSTANCE_URL`, or `SF_API_VERSION`.


```bash
pnpm exec kysoql --help
pnpm exec kysoql generate --help
```

The CLI uses the native REST Describe client, not JSforce. Authentication is
resolved by the configured/provider module, keeping credential acquisition out of
codegen itself. API version is pinned to `65.0` unless overridden. Match your
runtime query client's version and verify feature support in your org.

Without a configured `objects` list, omitting `--object` includes all queryable
objects from global Describe. For a
large org, start with an explicit list: `loadSchema` describes the selected
objects concurrently, without a configurable concurrency limiter or retry
policy. Object names are deduplicated and sorted; unknown or non-queryable
objects produce an error rather than an incomplete file. An empty programmatic
object list also means all queryable objects.

## Filter generated fields

The optional [`fields` map](/docs/codegen/field-filtering) supports one
exact-name `include` or `exclude` list per object, in both `kysoql.config.ts` and
`generateSchema` options. `loadSchema` also accepts it as a third argument.
Omitting a rule keeps that object's full described field set.

Filtering happens after Describe. It does not reduce Describe requests, change
Salesforce permissions, or implicitly select additional objects. Filtered objects
carry `fieldsComplete: false`, so typed `selectFields(...)` is unavailable for
them. Explicit `.select(...)` still works with the retained fields.

## Include relationship targets

Generating `Contact` alone does not automatically generate `Account` or `User`.
For a query selecting `Account.Name` or `CreatedBy.Alias`, generate those target
objects as well. Generate children used by `selectSubquery` and the referenced
objects used in `TYPEOF` branches.

The virtual polymorphic `.Type` qualifier is an exception: it is derived from
reference metadata and does not require every target object to be generated.

## What the schema preserves

The generator captures field value types and nullability, filter/sort/group/
aggregate capabilities, standard/custom field status, parent and child
relationships, reference targets, polymorphic flags, active picklist values,
object scopes, MRU capability, and supported Data 360 option capabilities.

Picklist fields are returned as strings; active values are separately retained
for supported multipicklist operations. Dates, datetimes, and times are strings
in query results. Location fields use `{ latitude, longitude }`. Unknown
Salesforce field types fall back conservatively; inspect the generated output
when introducing an unfamiliar field type.

Generated files have a `Do not edit manually` header. Empty metadata maps use
`Record<string, never>`. Imports are generated only when needed.

## Big object indexes

For custom Big Objects (`__b`), the native REST client also reads the ordered
composite index from Tooling API. Generated files export
`salesforceSchemaMetadata`; pass it to `Kysoql` so the compiler can validate
Big Object `WHERE` clauses against the same index order Salesforce enforces.

```ts
import { Kysoql } from "@kysoql/core";
import {
  salesforceSchemaMetadata,
  type SalesforceSchema,
} from "./kysoql/salesforce.generated";

const db = new Kysoql<SalesforceSchema>({
  schemaMetadata: salesforceSchemaMetadata,
});
```

Programmatic Describe clients can provide `describeBigObjectIndex(objectName)`
for any Big Object whose ordered index is available through another metadata
transport. Omitting runtime schema metadata preserves the previous compiler
behaviour.

## Knowledge categories

For `KnowledgeArticleVersion` and objects ending in `__kav`, the bundled CLI
also requests the visible category tree from the REST data-category resource.
The same discovered Knowledge tree is reused within a run. Visibility depends
on the connected user.

REST discovery does not cover `Question` here. Programmatic clients can provide
`describeDataCategoryGroups` when a different transport, such as SOAP, can supply
that metadata. The callback is optional; without it, only categories already
present in the supplied object descriptions can be emitted.

## Programmatic generation

The public API accepts a `SalesforceDescribeClient`, not a live schema attached
to `Kysoql`. It does not load `kysoql.config.ts`; pass options explicitly.
Programmatic relative output paths use the process working directory. Use the
bundled native factory, or implement the interface for another transport:

```ts
import { createRestDescribeClient, generateSchema } from "@kysoql/codegen";

export async function generateForOrg(instanceUrl: string, accessToken: string) {
  await generateSchema({
    client: createRestDescribeClient({ instanceUrl, accessToken, apiVersion: "65.0" }),
    objects: ["Account", "Contact"],
    fields: { Account: { include: ["Id", "Name"] } },
    output: "src/kysoql/salesforce.generated.ts",
  });
}
```

`createRestDescribeClient` also accepts a shared `RestClient` from `@kysoql/rest`,
including token-provider, cancellation, and timeout configuration. It validates
Describe metadata, checks that the returned object matches the requested name,
and loads full Knowledge category trees with `topCategoriesOnly=false`. Failed
taxonomy requests are not cached permanently. No JSforce dependency is installed
by the published codegen package.

```ts
import {
  generateSchema,
  loadSchema,
  renderSchema,
  type SalesforceDescribeClient,
} from "@kysoql/codegen";

export async function regenerate(client: SalesforceDescribeClient): Promise<void> {
  await generateSchema({
    client,
    objects: ["Account", "Contact"],
    output: "src/kysoql/salesforce.generated.ts",
    schemaName: "SalesforceSchema",
  });
}

export async function preview(client: SalesforceDescribeClient): Promise<string> {
  const objects = await loadSchema(client, ["Account", "Contact"]);
  return renderSchema(objects, "SalesforceSchema");
}
```

| Export | Contract |
| --- | --- |
| `createRestDescribeClient(clientOrOptions)` | Native validated Describe transport; accepts `RestClient` or `RestClientOptions`. |
| `defineConfig(config)` | Typed identity helper for a plain `KysoqlConfig` object. |
| `KysoqlConfig` | Optional `auth`, `apiVersion`, `objects`, `fields`, `output`, and `schemaName` for the CLI config file. |
| `ObjectFieldFilter` / `ObjectFieldFilters` | Mutually exclusive include/exclude rule, and the readonly object-name-to-rule map. |
| `generateSchema(options)` | Loads metadata and writes the file. Resolves to `void`; does not discover config files. |
| `loadSchema(client, requestedObjects?, fields?)` | Loads and validates descriptions, applies field rules, and returns a readonly list. |
| `renderSchema(objects, schemaName?)` | Renders supplied descriptions to a TypeScript string without network or filesystem access. |
| `SalesforceDescribeClient` | `describeGlobal()`, `describe(objectName)`, and optional `describeDataCategoryGroups(objectName)` / `describeBigObjectIndex(objectName)`. |
| `GenerateSchemaOptions` | Required `client` and `output`; optional `objects`, `fields`, and `schemaName`. |

The package exports the normalized Describe interfaces for objects, fields,
relationships, scopes, picklist entries, and category responses. Invalid
Describe payloads are rejected at the codegen boundary.

## Keep generated types current

Keep the generator command in an application script. Either commit generated
types and review diffs, or regenerate in a reproducible build step with secure
credentials. Do not make every application startup depend on Describe calls.
Generate separately for materially different org schemas; an interface generated
from one org is not proof that another org has the same capabilities.

Run application typechecks after regeneration. Do not suppress new errors with
`any`: they may identify a removed field, a missing relationship target, or a
changed capability. See [schema types](/docs/core/reference/schema-types) for a small
handwritten schema suitable for offline examples.

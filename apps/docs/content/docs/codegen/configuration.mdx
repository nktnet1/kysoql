Use a configuration file to make schema generation repeatable across developers
and CI. The file configures **`kysoql generate` only**. It does not create a
runtime query builder, configure a REST or JSforce executor, or change application
queries. Continue to construct your application client as shown in the
[quickstart](/docs/framework/getting-started/quickstart#4-configure-execution).

## Create a config

Place `kysoql.config.ts` in the directory where you run the CLI, usually beside
your application's `package.json`:

```ts title="kysoql.config.ts"
import { SalesforceAuth } from "@kysoql/auth";
import { defineConfig } from "@kysoql/codegen";
const salesforce = new SalesforceAuth({
  loginUrl: "https://login.salesforce.com",
  clientId: "external-client-app-id",
});

export default defineConfig({
  auth: () =>
    salesforce.jwtBearer({
      username: "integration@example.com",
      privateKey: "./salesforce-auth-key.pem",
    }),
  objects: ["Account", "Contact", "Opportunity", "User"],
  schemaName: "SalesforceSchema",
});
```

`defineConfig` provides editor completion and typechecking. It is a typed identity
helper, not a function that reads files, logs in, or generates a schema. A
`satisfies` annotation works as well:

```ts title="kysoql.config.ts"
import type { KysoqlConfig } from "@kysoql/codegen";

export default {
  objects: ["Account", "Contact"],
  output: "src/kysoql/salesforce.generated.ts",
} satisfies KysoqlConfig;
```

Run the generator; the `auth` provider resolves the Salesforce session when needed:

```bash
pnpm exec kysoql generate
```

## Settings

| Key | Type | Default | Behaviour |
| --- | --- | --- | --- |
| `auth` | `SalesforceAuthProvider` | `undefined` | Returns the Salesforce OAuth session used by CLI generation. May be overridden with `--auth`. |
| `apiVersion` | `string` | `65.0` | REST version for the CLI, without `v`. Overridden by `--api-version`. |
| `objects` | `readonly string[]` | All queryable objects | Salesforce API names. `[]` also means all queryable objects. Include relationship targets explicitly. |
| `fields` | `ObjectFieldFilters` | All described fields | Optional per-object exact include/exclude rules. See [field filtering](/docs/codegen/field-filtering). |
| `output` | `string` | `src/kysoql/salesforce.generated.ts` when `./src` exists; otherwise `kysoql/salesforce.generated.ts` | Override the generated file. Configured relative paths are resolved from the config directory; parent directories are created. |
| `schemaName` | `string` | `SalesforceSchema` | Generated interface name; must pass identifier validation. |

Export a plain object. Configuration factories, promises, and arrays of configs
are not supported. Optional settings may be omitted. Empty or whitespace-only
strings, wrong value types, and unknown properties are rejected before a
Salesforce connection is constructed. Prefer an explicit object list for a
large org; the current generator describes selected objects concurrently.

## Filter fields per object

Add a `fields` map to limit generated field declarations without changing which
objects are selected. Choose `include` or `exclude` for each object, not both:

```ts title="kysoql.config.ts"
import { defineConfig } from "@kysoql/codegen";

export default defineConfig({
  objects: ["Account", "Contact", "User"],
  fields: {
    Account: { include: ["Id", "Name", "Industry", "OwnerId"] },
    Contact: { exclude: ["Description"] },
  },
  output: "src/kysoql/salesforce.generated.ts",
});
```

`User` has no rule, so all its described fields remain available. An include
list must also contain fields used for filtering, sorting, grouping, and lookup
traversals, not just selected fields. Filtered objects deliberately disallow
`selectFields(...)`; use explicit selections instead. Rules are not access
controls. Read the [field filtering guide](/docs/codegen/field-filtering)
for validation, relationship dependencies, CLI overrides, and the programmatic API.

## Discovery and module loading

The CLI looks in the **current working directory only** for
`kysoql.config.ts`, `.mts`, `.cts`, `.js`, `.mjs`, or `.cjs`. It does not walk up
to a parent workspace. This prevents a workspace package from accidentally
using another application's org configuration.

If no file is found, CLI-only settings still work when an authentication provider is supplied with `--auth`. If more than one
supported file exists, generation fails with a message asking you to select one.
For an explicit path, a missing or invalid file is an error, not a silent
fallback to defaults.

TypeScript and ESM configs use a default export. `.cjs` and `.cts` files can also
use `module.exports`. The CLI uses a TypeScript-aware loader, so extensionless
relative imports of local helpers work. For example, a config may import a list
from `./salesforce-objects` when that module exports the required array. This
loader applies to the config, not your application runtime. Do not assume
application-specific bundler plugins or path aliases are available to it.

A config and its imports are **executable code**. Only run trusted configuration
files. In particular, do not give an untrusted pull request access to Salesforce
credentials just because the job only runs codegen.

## Overrides and paths

```bash
pnpm exec kysoql generate --config config/kysoql.sandbox.ts
pnpm exec kysoql generate --object Account --output tmp/account.ts
pnpm exec kysoql generate --no-config --auth config/salesforce.auth.ts --object Account --output tmp/account.ts
```

Precedence is **explicit CLI flags, then config settings, then built-in
defaults**. API version is **`--api-version`, then config `apiVersion`, then the
pinned `65.0` default**. Use a version
supported by your org; this is not automatic API-version negotiation. For example:

```bash
pnpm exec kysoql generate --api-version 65.0
```

A supplied `--object` list replaces the configured list; it does not
append to it. Settings not overridden on the command line remain configured.

`--config` is resolved relative to the current working directory. When `output` is
omitted, codegen writes `src/kysoql/salesforce.generated.ts` if the working
directory contains `src/`, otherwise `kysoql/salesforce.generated.ts`. A
configured relative `output` is resolved from the config file's directory, while
a CLI `--output` override is resolved from the current working directory. Absolute
paths stay absolute. For example, a config at `config/kysoql.sandbox.ts` with
`output: "../src/sandbox.generated.ts"` writes under the project `src/` directory.

`--no-config` disables discovery and evaluation entirely. It cannot be combined
with `--config`. Use it with no `--object` flags to explicitly generate all
queryable objects, ignoring any configured allowlist:

```bash
pnpm exec kysoql generate --no-config --auth config/salesforce.auth.ts --output src/all.generated.ts
```

## Multiple orgs and CI

Keep settings for different orgs in separate files and select one explicitly:

```json title="package.json"
{
  "scripts": {
    "schema:sandbox": "kysoql generate --config config/kysoql.sandbox.ts",
    "schema:production": "kysoql generate --config config/kysoql.production.ts"
  }
}
```

The `auth` provider chooses the authenticated org. Prefer `@kysoql/auth` with a
secret manager, key store, or refresh-token store rather than embedding tokens in
config. For multiple orgs, use separate providers/configs and output files.
Generated type files never contain credentials.

## Troubleshooting

**The wrong output file is being updated:** omitted output uses the working
directory's `src/kysoql/` or `kysoql/` default. Configured relative output paths
use the config directory; CLI output overrides use the working directory.

**A configured setting appears ignored:** check for flags in package scripts.
Explicit flags win. Also confirm the command is run from the config's directory
or uses `--config`; discovery does not search parents.

**The config fails to load:** read the reported filename and underlying import or
syntax error. Check the default export and any imported modules. Configuration
validation also rejects misspelled settings such as `out` instead of `output`.

**The editor accepts the config but generation fails:** `defineConfig` checks
types, not Salesforce metadata or authentication. Describe permissions, object
availability, token validity, and schema identifier validation still apply.
See [schema generation](/docs/codegen/schema-generation) and
[troubleshooting](/docs/core/reference/troubleshooting).

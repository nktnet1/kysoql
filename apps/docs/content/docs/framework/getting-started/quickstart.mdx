This walkthrough shows the complete native REST path: install Kysoql, configure
Salesforce JWT bearer authentication, generate the schema, execute a query, and
inspect the data returned by Salesforce.

Kysoql is ESM-only. The current packages require **Node.js `>=26.0.0 <27`**.

## 2. Configure Salesforce authentication

For a server-to-server integration, create a `SalesforceAuth` client and use the
JWT bearer flow. The private-key source is explicit: this example loads a PEM file.

```ts title="salesforce-auth.ts"
import { SalesforceAuth } from "@kysoql/auth";

const auth = new SalesforceAuth({
  loginUrl: "https://login.salesforce.com",
  clientId: "external-client-app-id",
});

export const getSalesforceSession = () =>
  auth.jwtBearer({
    username: "integration@example.com",
    privateKey: { type: "file", path: "./salesforce-auth-key.pem" },
  });
```

Use `{ type: "pem", value: "..." }` when the PEM comes from a secret manager, or
`{ type: "crypto-key", key }` when your application already owns an RS256
`CryptoKey`. Kysoql never guesses whether a string is a path or PEM content.

See [JWT bearer authentication](/docs/auth/flows/jwt-bearer) for the Salesforce
external-client-app setup.

## 3. Generate the Salesforce schema

Create `kysoql.config.ts` and tell codegen which objects your queries use:

```ts title="kysoql.config.ts"
import { defineConfig } from "@kysoql/codegen";
import { getSalesforceSession } from "./salesforce-auth";

export default defineConfig({
  auth: getSalesforceSession,
  objects: ["Account", "Contact"],
  schemaName: "SalesforceSchema",
});
```

Run the generator:

Because this example keeps its files at the project root, Kysoql writes
`kysoql/salesforce.generated.ts`. If your project already has a `src` directory,
the default output is `src/kysoql/salesforce.generated.ts`. The generated schema
describes the objects, fields, and relationships visible to the authenticated
Salesforce user.

## 4. Create a REST-backed query builder

Authenticate once to discover the Salesforce instance, then give the REST client
an access-token provider. `@kysoql/rest` caches the access token in memory. If
Salesforce rejects it with `401 INVALID_SESSION_ID`, the client calls the provider
with `refresh: true`, caches the replacement token, and replays that request once.

```ts title="db.ts"
import { Kysoql } from "@kysoql/core";
import { createRestExecutor } from "@kysoql/rest";
import { getSalesforceSession } from "./salesforce-auth";
import type { SalesforceSchema } from "./kysoql/salesforce.generated";

let session = await getSalesforceSession();
const instanceUrl = session.instanceUrl;

const executor = createRestExecutor({
  instanceUrl,
  apiVersion: "65.0",
  accessToken: async ({ refresh }) => {
    if (refresh) {
      const next = await getSalesforceSession();
      if (next.instanceUrl !== instanceUrl) {
        throw new Error("Salesforce instance changed; recreate the REST client.");
      }
      session = next;
    }
    return session.accessToken;
  },
});

export const db = new Kysoql<SalesforceSchema>({ executor });
```

JWT bearer does not issue a refresh token. The access token is deliberately kept
in memory rather than written to refresh-token storage; when it becomes invalid,
the private key is used to mint a new JWT assertion and obtain a replacement
access token.

## 5. Execute a query

```ts title="query.ts"
import { db } from "./db";

const accounts = await db
  .selectFrom("Account")
  .select(["Id", "Name"])
  .where("Name", "like", "Acme%")
  .orderBy("Name")
  .limit(25)
  .execute();

console.log(accounts);
```

Kysoql compiles that builder to:

```sql
SELECT Id, Name FROM Account WHERE Name LIKE 'Acme%' ORDER BY Name LIMIT 25
```

The native executor sends the equivalent Salesforce REST request and follows any
root query continuations automatically:

```text
GET /services/data/v65.0/query?q=SELECT+Id%2C+Name+FROM+Account+WHERE+Name+LIKE+%27Acme%25%27+ORDER+BY+Name+LIMIT+25
Authorization: Bearer <cached access token>
```

For example, Salesforce can return a response like this:

```json
{
  "totalSize": 1,
  "done": true,
  "records": [
    {
      "attributes": {
        "type": "Account",
        "url": "/services/data/v65.0/sobjects/Account/001000000000001AAA"
      },
      "Id": "001000000000001AAA",
      "Name": "Acme Corporation"
    }
  ]
}
```

`.execute()` resolves to the query rows, so `accounts` contains:

```json
[
  {
    "attributes": {
      "type": "Account",
      "url": "/services/data/v65.0/sobjects/Account/001000000000001AAA"
    },
    "Id": "001000000000001AAA",
    "Name": "Acme Corporation"
  }
]
```

The IDs and names above are illustrative. No matches return an empty array. The
selected field types come from your generated schema, while Salesforce REST record
metadata such as `attributes` is preserved by the native executor.

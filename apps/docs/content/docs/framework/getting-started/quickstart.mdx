This walkthrough uses a TypeScript application with `tsx`, configured as described in
[installation](/docs/framework/getting-started/installation), a Salesforce org with API
access, and an OAuth integration user allowed to describe and query `Account`
and `Contact`.

## 1. Define authentication

Resolve Salesforce sessions explicitly with `@kysoql/auth`; codegen does not read
access-token or instance-URL environment variables. For JWT bearer authentication,
pass the PEM file directly:

```ts title="salesforce-auth.ts"
import { SalesforceAuth } from "@kysoql/auth";

const auth = new SalesforceAuth({
  loginUrl: "https://login.salesforce.com",
  clientId: "external-client-app-id",
});

export const getSalesforceSession = () =>
  auth.jwtBearer({
    username: "integration@example.com",
    privateKey: "./salesforce-auth-key.pem",
  });
```

`privateKey` also accepts a raw PEM string, a file URL, or an existing `CryptoKey`.
Raw string values are trimmed before parsing, so a secret-manager value can be
passed directly without manually decoding PKCS#8. Relative file paths resolve from
`process.cwd()`; use `new URL("./salesforce-auth-key.pem", import.meta.url)` for
module-relative loading. Keep private keys and other long-lived credentials outside
source control. See [authentication](/docs/auth)
and [security](/docs/core/reference/security).

## 2. Configure and generate your schema

Create `kysoql.config.ts` beside the application's `package.json`:

```ts title="kysoql.config.ts"
import { defineConfig } from "@kysoql/codegen";
import { getSalesforceSession } from "./salesforce-auth";

export default defineConfig({
  auth: getSalesforceSession,
  objects: ["Account", "Contact"],
  schemaName: "SalesforceSchema",
});
```

Run from that directory:

```bash
pnpm run schema:generate
```

The script runs `kysoql generate`, which discovers the config and invokes its auth
provider only after configuration validation succeeds. See
[configuration](/docs/codegen/configuration) for overrides, multiple orgs,
and path rules. The CLI also works [without a config](/docs/codegen/schema-generation#cli-reference)
when `--auth <module>` is supplied.

With the default layout, the generated file is `src/kysoql/salesforce.generated.ts`
because this application has a `src` directory. The output describes the fields
and relationships visible to the connected user. It is a TypeScript type
definition, not a cache of records. Regenerate it when
metadata changes. Add any other objects used in your queries to `objects`;
codegen does not automatically include relationship targets.

## 3. Compile without making a query request

Create `src/compile.ts`:

```ts title="src/compile.ts"
import { Kysoql } from "@kysoql/core";
import type { SalesforceSchema } from "./kysoql/salesforce.generated";

const db = new Kysoql<SalesforceSchema>();
const compiled = db
  .selectFrom("Account")
  .select(["Id", "Name"])
  .where("Name", "like", "Acme%")
  .orderBy("Name")
  .limit(25)
  .compile();

console.log(compiled.soql);
```

Run it:

```bash
pnpm run typecheck
pnpm exec tsx src/compile.ts
```

Expected SOQL:

```sql
SELECT Id, Name FROM Account WHERE Name LIKE 'Acme%' ORDER BY Name LIMIT 25
```

`compile()` creates `{ soql, query }`, where `query` is the typed operation tree.
It neither authenticates nor sends a request. A fresh process can run this
compile-only example without Salesforce credentials after the schema exists.

## 4. Configure execution

Create `src/db.ts`:

```typescript title="src/db.ts"
import { Kysoql } from "@kysoql/core";
import { createRestExecutor } from "@kysoql/rest";
import { getSalesforceSession } from "./salesforce-auth";
import type { SalesforceSchema } from "./kysoql/salesforce.generated";

const session = await getSalesforceSession();

export const executor = createRestExecutor({
  instanceUrl: session.instanceUrl,
  accessToken: session.accessToken,
  apiVersion: "65.0",
});

export const db = new Kysoql<SalesforceSchema>({ executor });
```

This reuses the `@kysoql/auth` provider from step 1 and passes the resulting session
to the native REST executor, without JSforce. JWT bearer uses a server-side private
key and does not require an interactive login or stored refresh token. For
long-running services that need refresh-token rotation, see the REST
[authentication integration](/docs/rest/authentication). Align the executor API
version with schema generation and verify target-org feature support.

Create `src/query.ts`:

```ts title="src/query.ts"
import { db } from "./db";

async function main(): Promise<void> {
  const accounts = await db
    .selectFrom("Account")
    .select(["Id", "Name"])
    .where("Name", "like", "Acme%")
    .orderBy("Name")
    .limit(25)
    .execute();

  for (const account of accounts) {
    console.log(account.Id, account.Name);
  }
}

main().catch((error: unknown) => {
  // Do not log tokens, full SOQL, or complete Salesforce responses in production.
  console.error(error instanceof Error ? error.message : "Query failed");
  process.exitCode = 1;
});
```

```bash
pnpm run typecheck
pnpm start
```

The result is a readonly array of rows containing the selected fields. No matches
return an empty array. Types come from your generated schema, including field
nullability; fields you did not select are not in the inferred result.

## 5. Query related contacts

```ts
import { db } from "./db";

const accounts = await db
  .selectFrom("Account")
  .select(["Id", "Name"])
  .selectSubquery("Contacts", (contacts) =>
    contacts.select(["Id", "LastName"]).orderBy("LastName").limit(10),
  )
  .limit(25)
  .execute();

for (const account of accounts) {
  for (const contact of account.Contacts.records) {
    console.log(account.Name, contact.LastName);
  }
}
```

A child relationship is a Salesforce query-result envelope, not a direct array.
The adapter drains root pages, not nested child envelopes; see
[relationships](/docs/framework/guides/relationships#read-child-results).

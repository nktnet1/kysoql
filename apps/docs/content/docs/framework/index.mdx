Kysoql is a **Kysely-inspired query builder for Salesforce Object Query Language
(SOQL)** using your org's Describe metadata. Select fields, filter records,
traverse relationships, and build aggregate reports with inferred TypeScript
results.

The inspiration is in the TypeScript API design, not SQL compatibility.
[Kysely](https://kysely.dev/) is a SQL query builder; Kysoql is not Kysely, does
not depend on Kysely, and is not a Kysely dialect or adapter. Salesforce SOQL is
the target language and its rules are authoritative.

It is a query builder, not an ORM: it does not create records, update records,
manage transactions, or generate Salesforce objects. You can compile queries
without a connection, execute API queries through an adapter, or produce
compile-only SOQL for an Apex caller.

## Kysely-inspired, SOQL-native

Kysoql intentionally carries over familiar ideas such as immutable fluent
builders, `selectFrom`, `select`, `where`, `orderBy`, `$if`, `$call`, result-type
helpers, and query/result plugins. Those similarities are ergonomic rather than a
compatibility promise.

Where SQL and SOQL differ, Kysoql follows SOQL. Relationship paths, parent-to-child
subqueries, and semi-joins replace arbitrary SQL joins; ordinary REST queries
compile values into escaped SOQL literals rather than producing a SQL-style
parameter array; mutations and transactions are outside a SOQL query builder; and
methods are omitted when Salesforce does not support the corresponding operation.

## Start here

Follow the [quickstart](/docs/framework/getting-started/quickstart) to install the
packages, generate an org-specific schema, compile a query, and execute it through
native REST, without JSforce.

```ts
import { Kysoql } from "@kysoql/core";
import type { SalesforceSchema } from "./kysoql/salesforce.generated";

const db = new Kysoql<SalesforceSchema>();

const query = db
  .selectFrom("Account")
  .select(["Id", "Name"])
  .where("Name", "like", "Acme%")
  .orderBy("Name")
  .limit(25);

console.log(query.compile().soql);
// SELECT Id, Name FROM Account WHERE Name LIKE 'Acme%'
// ORDER BY Name LIMIT 25
```

This example only compiles. Calling `execute()` requires an
[executor](/docs/rest/execution).

## Packages

| Package | Purpose |
| --- | --- |
| [`@kysoql/core`](/docs/core) | Query builders, schema types, SOQL compiler, and executor contract. |
| [`@kysoql/rest`](/docs/rest) | Native query/QueryAll execution, counts, pagination, token-provider renewal, and cancellation. |
| [`@kysoql/auth`](/docs/auth) | Private-key JWT bearer server-to-server auth, other supported Salesforce OAuth flows, and refresh-token storage. |
| [`@kysoql/codegen`](/docs/codegen) | Describe-driven schema generation and the `kysoql` CLI. |
| [`@kysoql/jsforce`](/docs/jsforce) | Optional adapter for applications that already use JSforce. |

Kysoql is split into focused `@kysoql/*` packages so applications can install
only the pieces they need. Keep the Kysoql packages in an application on aligned
versions.

## What validation does and does not guarantee

Generated types constrain object names, field names, relationship paths, values,
and capabilities such as `filterable` or `groupable`. Builder and compiler
validation also reject many invalid clause combinations. Neither replaces the
Salesforce server: org permissions, API versions, enabled features, current
metadata, query selectivity, and runtime governor limits still apply.

Beta and pilot features are [explicitly separated](/docs/core/advanced/experimental),
not presented as ordinary production features. `soql.raw()` is the explicit unsafe
escape hatch for trusted SOQL syntax the builder does not model.

`@kysoql/rest` consumes Salesforce bearer access tokens; `@kysoql/auth` is the
full authentication package. Keeping identity acquisition separate from query
execution lets applications choose the Salesforce flow and token store that match
their architecture without coupling the SOQL executor to browser or server login
state.

<SalesforceReference title="Authorization Through External Client Apps or Connected Apps and OAuth 2.0" href="https://developer.salesforce.com/docs/platform/api-rest/guide/intro-oauth-and-connected-apps.html" />

See [`@kysoql/auth`](/docs/auth) for current web-server/PKCE, refresh, client
credentials, JWT, SAML, token exchange, device, hybrid, Code and Credentials, and
first-party headless flows.

## Existing access token

```ts
import { createRestExecutor } from "@kysoql/rest";

export function executorForSession(instanceUrl: string, accessToken: string) {
  return createRestExecutor({ instanceUrl, accessToken, apiVersion: "65.0" });
}
```

Use the `instance_url` returned by Salesforce authentication, not a generic login
host. A static token is never refreshed automatically.

## Refresh-token-backed provider

```ts
import {
  createMemoryRefreshTokenStore,
  SalesforceAuth,
} from "@kysoql/auth";
import { createRestExecutor } from "@kysoql/rest";

export async function createRefreshingExecutor(refreshToken: string) {
  const auth = new SalesforceAuth({
    loginUrl: "https://example.my.salesforce.com",
    clientId: "oauth-client-id",
  });
  const sessionAuth = auth.storedRefreshToken({
    initialRefreshToken: refreshToken,
    refreshTokenStore: createMemoryRefreshTokenStore(),
  });
  const session = await sessionAuth.getSession();

  return createRestExecutor({
    instanceUrl: session.instanceUrl,
    accessToken: sessionAuth.accessTokenProvider,
  });
}
```

The REST client lazily acquires a provider token and caches it. Only a `401`
Salesforce response containing `INVALID_SESSION_ID` requests another token with
`refresh: true`; the failed HTTP operation is replayed at most once. Concurrent
requests on one REST client share its in-flight acquisition or refresh.

The auth manager separately single-flights the refresh exchange, reads the latest
stored refresh token, and persists rotation before returning a refreshed session.
For shared Redis state across multiple processes, add application-level distributed
locking when refresh-token rotation is enabled.

## Compatibility helpers in @kysoql/rest

`@kysoql/rest` retains its existing `authenticateClientCredentials()` and
`refreshAccessToken()` exports for compatibility. New authentication code should prefer `SalesforceAuth` from `@kysoql/auth`,
which binds common client configuration and exposes the complete flow and storage
surface. The standalone functions remain available for lower-level composition. REST execution itself does not require either helper if your
application already has a valid bearer token.

## Security boundaries

Generated Salesforce types do not grant object, field, or record access.
Authentication inherits the permissions of the Salesforce identity associated
with the token. Keep client secrets, private keys, refresh tokens, and production
access tokens out of source code and logs. See [security](/docs/core/reference/security)
and [refresh-token storage](/docs/auth/storage).

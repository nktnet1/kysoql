---
title: "Scopes, visibility, and MRU tracking"
description: "Use generated object capabilities for root-query Salesforce clauses."
---

These methods apply to root queries. They are not general options objects and
are intentionally absent from relationship-subquery builders. Configure them
before entering the narrower Apex context when applicable.

## USING SCOPE

```ts
import { db } from "./db";

const mine = db
  .selectFrom("Account")
  .select(["Id", "Name"])
  .usingScope("mine")
  .where("Name", "like", "Acme%");
```

The accepted scope is the selected object's generated `supportedScopes` union.
`"mine"` is valid only when your generated metadata lists it. Repeated calls
replace the previous scope; the compiler places `USING SCOPE` immediately after
`FROM`. Root record, aggregate, and count builders expose it where metadata
allows. It is not available inside a child subquery.

## RecordVisibilityContext

```ts
import { db } from "./db";

const query = db
  .selectFrom("Account")
  .select(["Id", "Name"])
  .withRecordVisibilityContext({
    maxDescriptorPerRecord: 100,
    supportsDomains: true,
    supportsDelegates: false,
  });
```

The supported options are `maxDescriptorPerRecord`, `supportsDomains`, and
`supportsDelegates`. At least one must be supplied. The descriptor count is a
non-negative safe integer and the two capability flags are booleans. Unknown
options are rejected. Repeated calls replace the whole context rather than
merging it.

This emits the Salesforce `WITH RecordVisibilityContext (...)` form. It is not
a replacement for permissions or application authorisation. The compiler
rejects combining it with `WITH DATA CATEGORY`, `WITH UserId`, or Apex
`WITH USER_MODE`/`WITH SYSTEM_MODE` because they occupy the same filtering slot.

## FOR VIEW and FOR REFERENCE

```ts
import { db } from "./db";

const query = db
  .selectFrom("Account")
  .select(["Id", "Name"])
  .limit(20)
  .forView();
```

`forView()` and `forReference()` require generated `mruEnabled` capability.
Legacy handwritten schemas that leave that capability unspecified remain
permissive; generated schemas preserve the actual Describe flag. Repeated calls
replace the previous mode, so the query cannot accumulate both modes.

These clauses participate in Salesforce Most Recently Used tracking and can
have observable side effects. Do not attach them to background exports or
read-only-looking helpers without considering that behaviour. Root aggregate
and count builders also model the clauses, but Salesforce remains responsible
for object/context support. External objects reject them.

Knowledge-specific `UPDATE` tracking is separate; see
[Knowledge and feeds](/docs/advanced/knowledge-and-feeds).

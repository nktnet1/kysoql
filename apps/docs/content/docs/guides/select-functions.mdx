Selected functions use a callback and an explicit alias. They can accompany
ordinary record fields, but cannot be combined with a `TYPEOF` selection.
Aliases must be valid, unique identifiers rather than raw SQL fragments.

## Translated labels

```ts
import { db } from "./db";

const opportunities = db
  .selectFrom("Opportunity")
  .select(["Id", "StageName"])
  .select(({ fn }) => fn.toLabel("StageName").as("stageLabel"));
```

`toLabel` accepts generated picklist and multipicklist fields, including supported
parent paths. Output is a string with source/relationship nullability. The stored
`StageName` and translated `stageLabel` serve different purposes: use stable
stored values for application logic and translated labels for presentation.

Translated filtering is available separately in `WHERE`:

```ts
import { db } from "./db";

const query = db
  .selectFrom("Opportunity")
  .select(["Id", "StageName"])
  .where((eb) => eb(eb.fn.toLabel("StageName"), "like", "Pros%"));
```

The field must be filterable. Translated comparisons support `=`, `!=`, and
`like`, not arbitrary ordered/list operators. Filtering translated
`CurrencyIsoCode` and the standard `Division` field is intentionally rejected.
The SELECT helper is not a general translated ORDER BY facility.

## Currency conversion

```ts
import { db } from "./db";

const opportunities = db
  .selectFrom("Opportunity")
  .select(["Id", "Amount"])
  .select(({ fn }) => fn.convertCurrency("Amount").as("convertedAmount"))
  .orderBy("Amount", "desc");
```

`convertCurrency` is a record SELECT function over currency fields. It uses the
querying user's currency and returns a numeric value with source nullability.
Order using the supported field/expression surface, not the selected alias.
It is not a client-side exchange-rate service or an aggregate conversion helper.

Use [`soqlCurrency`](/docs/guides/literals#currency-literals) for an ISO-coded
filter literal; that is separate from converting selected output.

## Localized display strings

```ts
import { db } from "./db";

const opportunities = db
  .selectFrom("Opportunity")
  .select("Id")
  .select(({ fn }) => [
    fn.format("CloseDate").as("localizedCloseDate"),
    fn.format(fn.convertCurrency("Amount")).as("localizedAmount"),
  ]);
```

`format` accepts `currency`, `double`, `int`, `percent`, `date`, `datetime`, and
`time` fields, including supported parent paths. It can wrap an unaliased
`convertCurrency` expression. Result values are strings with the source's
nullability, not numbers/dates suitable for further calculations.

Aggregate results can also format unaliased field aggregates:

```ts
import { db } from "./db";

const totals = db
  .selectFrom("Opportunity")
  .select(({ fn }) => [
    fn.format(fn.count("Id")).as("displayCount"),
    fn.format(fn.sum("Amount")).as("displayAmount"),
  ]);
```

Apply `.as(...)` to the outer function. Do not pass an already aliased expression
into `format`. Bare `COUNT()` is not a field aggregate to format. Preserve the
raw values separately when a downstream consumer needs arithmetic, sorting, or
locale-independent serialization.

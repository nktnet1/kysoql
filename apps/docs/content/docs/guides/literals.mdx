## Temporal values

Salesforce returns temporal fields as strings, but the filter API deliberately
requires structured literals so ordinary string values cannot be mistaken for
SOQL date syntax.

```ts
import { soqlDate, soqlDateTime } from "@kysoql/core";
import { db } from "./db";

const query = db
  .selectFrom("Opportunity")
  .select(["Id", "CloseDate", "CreatedDate"])
  .where("CloseDate", ">=", soqlDate("2026-09-01"))
  .where("CreatedDate", "<", soqlDateTime("2026-10-01T00:00:00Z"));
```

| Factory | Accepted format | Example |
| --- | --- | --- |
| `soqlDate(value)` | `YYYY-MM-DD` | `soqlDate("2026-09-01")` |
| `soqlDateTime(value)` | Date plus `Thh:mm:ss`, optional three-digit milliseconds, and `Z` or an explicit offset | `soqlDateTime("2026-09-01T09:00:00+10:00")` |
| `soqlTime(value)` | `hh:mm:ssZ` or `hh:mm:ss.SSSZ` | `soqlTime("09:30:00.000Z")` |

The helpers validate calendar dates, clock values, and offsets. This
implementation accepts years 1700 through 4000 and UTC offsets no larger than
14 hours; an offset at 14 hours must have zero minutes. Invalid values throw
`TypeError`. Fractional seconds, when present, must contain exactly three digits.

These helpers validate and preserve input; they do not convert between timezones.
To use a JavaScript `Date` for a datetime filter, explicitly convert it with
`toISOString()` and pass that string to `soqlDateTime`.

```ts
import { soqlDateTime, soqlTime } from "@kysoql/core";

const instant = soqlDateTime(new Date("2026-09-01T00:00:00Z").toISOString());
const timeOfDay = soqlTime("09:30:00Z");
```

A Date field needs a date literal, a DateTime field needs a datetime literal,
and a Time field needs a time literal. Date and DateTime also support the
relative literals below. The compiler emits these literals unquoted.

## Relative dates

```ts
import { soqlRelativeDate } from "@kysoql/core";
import { db } from "./db";

const query = db
  .selectFrom("Opportunity")
  .select(["Id", "CloseDate"])
  .where("CloseDate", "=", soqlRelativeDate("THIS_MONTH"))
  .where("CreatedDate", "=", soqlRelativeDate("LAST_N_DAYS", 30));
```

Fixed values supported by this implementation:

```text
TODAY YESTERDAY TOMORROW
LAST_WEEK THIS_WEEK NEXT_WEEK
LAST_MONTH THIS_MONTH NEXT_MONTH
LAST_90_DAYS NEXT_90_DAYS
LAST_QUARTER THIS_QUARTER NEXT_QUARTER
LAST_YEAR THIS_YEAR NEXT_YEAR
LAST_FISCAL_YEAR THIS_FISCAL_YEAR NEXT_FISCAL_YEAR
LAST_FISCAL_QUARTER THIS_FISCAL_QUARTER NEXT_FISCAL_QUARTER
```

Parameterized families accept a second, non-negative safe-integer argument:

```text
LAST_N_DAYS NEXT_N_DAYS N_DAYS_AGO
LAST_N_WEEKS NEXT_N_WEEKS N_WEEKS_AGO
LAST_N_MONTHS NEXT_N_MONTHS N_MONTHS_AGO
LAST_N_QUARTERS NEXT_N_QUARTERS N_QUARTERS_AGO
LAST_N_YEARS NEXT_N_YEARS N_YEARS_AGO
LAST_N_FISCAL_QUARTERS NEXT_N_FISCAL_QUARTERS N_FISCAL_QUARTERS_AGO
LAST_N_FISCAL_YEARS NEXT_N_FISCAL_YEARS N_FISCAL_YEARS_AGO
```

Use `soqlRelativeDate("LAST_N_DAYS", 30)`, not a single raw
`"LAST_N_DAYS:30"` string. The resulting SOQL value is `LAST_N_DAYS:30`.
Invalid family names throw `TypeError`; invalid counts throw `RangeError`.
The helper accepts zero, but Salesforce determines each literal's range and
calendar semantics. These are server-evaluated ranges, not client-calculated
rolling durations. Consult the official
[date literal reference](https://developer.salesforce.com/docs/platform/salesforce-soql-sosl/guide/sforce-api-calls-soql-select-dateformats.html)
for timezone, fiscal-calendar, and boundary behaviour.

## Currency literals

```ts
import { soqlCurrency } from "@kysoql/core";
import { db } from "./db";

const query = db
  .selectFrom("Opportunity")
  .select(["Id", "Amount"])
  .where("Amount", ">=", soqlCurrency("USD", 5000));
// WHERE Amount >= USD5000
```

`soqlCurrency(isoCode, value)` requires exactly three uppercase ASCII letters
and a finite number. It validates the shape, not whether that currency is enabled
in your org. ISO-coded literals are supported on currency fields in `WHERE`,
not arbitrary numeric fields or every expression context.

An `IN` or `NOT IN` list must contain either bare field values or ISO-coded
currency literals. Do not mix the two in one list. Currency conversion in
selected output is a different feature: see
[`convertCurrency`](/docs/guides/select-functions#currency-conversion).
